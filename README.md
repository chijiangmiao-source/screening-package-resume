# 影展放映素材交付站

面向影展高码率放映素材的断点续传交付系统：Vue 单页前端按 **固定 1 MiB（1048576 字节）** 分块上传，Go API 用 **SQLite** 记录会话与已确认分块元数据，分块内容持久化到本地数据卷，全部分块到齐后按序组装、整文件 SHA-256 校验通过才以**原子改名**发布成品。

## 快速开始

```bash
docker compose up --build -d        # 启动 web + api
docker compose --profile verify up --build verify          # 运行一次性验收服务（真实联调，非假接口）
docker compose --profile verify up --exit-code-from verify verify   # 需要退出码时
```

- Web 页面：`http://localhost:${WEB_PORT:-8081}`
- API：`http://localhost:${API_PORT:-8080}`（如 `curl localhost:8080/api/health`）
- 宿主端口可覆盖：`WEB_PORT=9000 API_PORT=9001 docker compose up --build -d`

数据保存在名为 `delivery-data` 的卷中（SQLite 库、分块文件、成品 artifacts），删除卷即清空全部状态。

## 交付协议

1. **创建会话** `POST /api/sessions`
   提交 `filename`、`total_bytes`、`chunk_count`、`file_sha256`（整文件 SHA-256，64 位小写十六进制）。
   `chunk_count` 必须与 `ceil(total_bytes / 1048576)` 一致，否则 400。
   请求体必须是**唯一一个** JSON 值：合法对象后再附加第二个对象或任何尾随字节一律 400（仅尾随空白合法）；
   `chunk_count` 必须为正，`total_bytes` 上限 1 TiB，任何算不出有效分块范围的元数据（含 int64 溢出导致的负分块数）都被拒绝。
   可选字段 `reuse_artifact: true` 声明**成品复用意愿**：服务端按整文件摘要与总字节数查找已完成会话，
   并复核其成品文件仍在卷上且长度一致；命中则新会话直接以 `completed` 创建（`final_sha256` 就绪、
   `artifact_source` 指向来源会话、零分块上传），未命中（无匹配、成品缺失或长度异常）则退回普通上传会话，
   不误报完成。旧客户端不带该字段时一律返回新建上传会话。

   可选字段 `create_token`（32 位小写十六进制）是**创建幂等令牌**：前端为每次“开始上传”先生成 16
   随机字节的令牌并在本地保存，再发出创建请求。它解决“服务端已受理但响应因超时丢失”的窗口——
   页面不认识新会话、可能重复建空会话，或错过已经命中的成品复用：
   - 同一令牌搭配**完全相同**的元数据（文件名、字节数、分块数、整文件摘要、复用意愿）再次请求：
     在**同一事务内**判定为重试，返回原会话的**当前快照**（`200`），不重复插入记录、不重复建分块目录。
     因此首次若是成品复用命中，重试仍得到同一个已完成会话；若期间已有分块确认，快照直接反映最新进度。
   - 同一令牌搭配**不同**文件名、字节数、分块数、摘要或复用意愿：返回 `409` 冲突，
     **原会话一行都不改动**，页面明确提示需“重新开始”（生成新令牌），不得再重试本次创建。
   - 全新令牌正常 `201` 建会话。两个携带同一全新令牌的并发请求会在 `BEGIN IMMEDIATE` 事务上串行，
     恰好一个 `201`、其余 `200` 指向同一会话（唯一索引兜底）。
   - 不带令牌的旧客户端行为完全不变：每次请求都得到相互独立的新会话。
   令牌列在 SQLite 中**可空且唯一**（部分唯一索引，多条 NULL 不冲突），随迁移自动补齐，
   进程重启后仍可凭令牌解析到原会话。
2. **上传分块** `POST /api/sessions/{id}/chunks/{index}`
   原始字节 + `X-Chunk-SHA256` 头（**必须**小写十六进制；全大写等非小写写法即使数值正确也返回 400，分块保持未确认）。除最后一块外每块必须**恰好 1048576 字节**，
   最后一块长度由总字节数唯一确定（`total_bytes - 1048576 × (chunk_count - 1)`），不符即 400。
   - 同序号同摘要重复提交 → `200`，幂等成功，**不重复计数**；
   - 同序号不同内容 → `409`，会话立即冻结为 `failed`，之后一切写入与组装均被拒绝。
3. **查询会话** `GET /api/sessions/{id}`
   返回状态、已确认字节数、缺块列表 `missing_chunks`、完成摘要 `final_sha256`、失败原因。
   刷新或重开页面后，前端凭会话标识（localStorage 自动保存，或手动粘贴）拉取缺块列表，**仅补传缺块**。
4. **组装发布** `POST /api/sessions/{id}/assemble`
   仅当全部分块存在时受理：按序写入临时文件并逐块复核摘要，整文件 SHA-256 与申报一致才
   `rename` 原子发布到 `artifacts/` 并标记 `completed`；摘要不符则标记 `failed`，临时文件删除，**成品不可见**。
5. **成品下载** `GET /api/sessions/{id}/download`
   仅 `completed` 会话可下载，响应带 `Content-Disposition`（沿用原始文件名）与 `Accept-Ranges: bytes`：
   - 不带 `Range`：整文件 `200` 返回；
   - **单段** `Range`（如 `bytes=1048576-`）：`206` 并返回准确的 `Content-Range` / `Content-Length`，
     网络中断后可从已接收字节偏移继续，无需重传整个文件；
   - 越界、倒置、**多段**或格式错误的范围：`416` + `Content-Range: bytes */<size>`，**无正文**；
   - 上传中 / 已失败会话：`409`；数据库已完成但成品文件缺失：`410`；未知会话：`404`。
   复用会话（`artifact_source` 非空）的下载正文读取**被复用的成品文件**，
   而 `Content-Disposition` 文件名取自**本次提交**；查询与下载始终使用新会话标识。
6. **进度事件流** `GET /api/sessions/{id}/events`（SSE）
   客户端按会话标识订阅：连接建立后**首先收到完整快照**（`event: snapshot`，
   `data` 为与 `GET /api/sessions/{id}` 同构的会话对象），之后仅在
   已确认字节、缺块列表、状态、完成摘要或失败原因变化时推送 `event: update`。
   每条事件的 SSE `id` / 载荷 `seq` 为 SQLite 持久化的**递增进度序号**：
   会话创建时为 1；分块确认、冲突冻结、组装完成/失败均在**原状态事务内** +1
   （幂等重复分块不改变状态、不递增、不推送）。
   - 每 15 秒发送一行心跳注释（`: ping`）保持长连接；
   - 重连携带最后序号（`?after=N`，或浏览器原生 `Last-Event-ID` 头）：
     期间无增量时仍返回当前序号的完整快照，断线期间已有提交时快照直接是最新状态
     （不逐条补旧增量，因此不会漏序也不会乱序）；
   - 序号持久化在 SQLite 中，**进程重启后继续递增**；
   - 未知会话：`404` JSON（不升级为事件流）。

## 目录结构

```

  main.go       入口；内置 -healthcheck 供容器健康检查
  store.go      SQLite 模式（含 artifact_source、progress_version、create_token/reuse_requested
                列与令牌唯一索引的迁移）、会话/分块元数据、
                确认/冻结/完成与进度序号在同一事务内递增、
                创建令牌在 BEGIN IMMEDIATE 单事务内判重（同元数据回放当前快照、异元数据冲突）、
                成品复用候选查找（摘要+总字节数匹配，成品文件存在且长度一致）、数据卷路径
  events.go     进度事件中枢与 SSE 接口：订阅先得快照、仅在序号前进时推送更新、
                ?after=N / Last-Event-ID 重连续传、15s 心跳、跨连接扇出
  handlers.go   HTTP 接口：会话（可选成品复用 + 可选创建令牌幂等）、分块、组装、幂等与冲突冻结、

                成品缺失 410；创建令牌：丢响应重试同会话当前快照且仅一条记录/一个分块目录、
                复用命中回放、元数据/复用意愿冲突 409 不改原会话、并发同令牌一次 201 其余 200、

  src/App.vue   会话页以事件流替代三秒轮询刷新进度区；暂断提示“实时更新已中断”，

                每次“开始上传”先生成并本地保存创建令牌，创建响应丢失时显示“重试创建”
                （同令牌+已算摘要），令牌冲突时明确提示“重新开始”

          用同一数据卷证明进度序号跨进程持久并继续递增
docker-compose.yml  web / api / verify 三服务，WEB_PORT、API_PORT 可覆盖；
                    api-peer 仅在运行 verify（profile）时随验收启动
```

## 页面可观测性

页面实时显示：已确认字节数 / 总字节数、已确认分块数、**缺块列表**、进度条、
`uploading / completed / failed` 状态徽章、**完成摘要**（绿色）与失败原因（红色），
并保留事件日志——续传成功与冲突失败都能被直接观察。
会话进入 `completed` 后出现**成品下载**区域：文件名、总字节数与下载按钮，
浏览器下载沿用原始文件名；下载不可用（409 未发布 / 410 成品缺失）时原因直接显示在该区域。
复用命中的交付在会话状态区显示**已复用成品**（含来源会话标识），下载区域同步标注本次未重新上传分块。

### 实时进度事件流

会话状态区通过 SSE 实时刷新（不再需要手动刷新页面）：标题旁显示绿色“实时”徽章；
连接暂断时出现黄色**“实时更新已中断，正在自动重连…”**提示并在约 2 秒后自动重连
（重连 URL 携带最后序号，无增量时仍先收到当前快照）。
事件流只负责**刷新进度区**——重连期间上传/续传/组装等控制完全不受影响，
另一台工作站确认的分块或完成的发布会即时反映到本页（可据此判断何时交给放映团队）。
浏览器不支持 EventSource 时自动退回原来的 3 秒轮询并在状态区说明。

## 网络中断与续传

- 所有请求带 60s 超时，半开连接不会让页面永远卡在"上传中"。
- **创建响应丢失**：点“开始上传”时页面先生成创建令牌并写入 localStorage，再发创建请求。
  若服务端已受理而响应超时/断网丢失，页面进入“创建响应丢失，可安全重试”，点“重试创建”
  复用**同一令牌与已算出的整文件摘要**（无需重算、无需重选之外的操作）：服务端在单事务内
  判重，已建会话则返回其当前快照（`200`），未建则照常 `201`，不会留下无法识别的空会话，
  也不会错过首次已经命中的成品复用。刷新页面后若本地只剩令牌，重选同一文件点“校验并续传”
  即凭令牌取回原会话。
- **创建令牌冲突**：同一令牌搭配不同文件名、字节数、分块数、摘要或复用意愿时接口返回 `409`，
  原会话保持不变；页面明确提示并提供“重新开始（生成新令牌）”，切勿再重试冲突的创建。
- 分块上传幂等，网络抖动时自动按指数退避重试（最多 5 次，不含首次尝试），页面显示"正在自动重试"。
- 重试耗尽后进入**"连接中断，可续传"**状态：会话已保存、已确认字节不丢失，
  页面每 3 秒自动重新查询缺块列表并续传，也可点"立即续传"手动触发；
  恢复后仅补传服务器仍缺失的分块，无需重新选择文件之外的任何操作。
- 组装请求遇断网同样进入该状态，恢复后先重新查询会话再决定补传或重新组装。
